# 原程序解析规则 —— 全部由**黑盒探针实测**得到

> 方法：造小 MIDI 喂给原程序的内核（`load_score` → `Score`），看它吐出什么。
> 比读字节码可靠 —— 输出就是规则本身。探针脚本：`../.workbuddy/analysis/probe_midi.py`

## 一、已吃准的规则（重写版按这些实现）

### 头信息

| 项 | 规则 | 证据 |
|---|---|---|
| 计时方式 | 只认 PPQ；`division` 高位为 1（SMPTE）直接报错 | probe ⑪ |
| `division == 0` | 报"文件坏了" | 代码常量 |
| 默认 tempo | 没有 tempo 事件时按 **120 BPM**（500000us） | probe ① 无 tempo 却 bpm=120 |
| `bpm` | `round(60_000_000 / tempo_us)` | probe ⑦ tempo=500000 → 120 |
| 拍号 | `beats_per_bar = 分子 × 4 ÷ 分母`（换算成四分音符拍） | 6/8→3.0、1/8→0.5、2/2→4.0、12/8→6.0 |
| `meter_den` | = 分母本身（4/8/2） | 同上 |
| `unit_beats` | MIDI 恒为 1.0 | 全部探针 |
| `tonic_index` | **恒为 0 —— 调号（FF 59）被完全忽略** | probe ⑧：2 个升号，C 音仍是音级 1 |
| `octave_shift` | MIDI 恒为 0 | 全部探针 |
| `title` | 取**文件名主干**（不是 MIDI 里的音轨名） | probe 文件名 probe_a → title='probe_a' |
| `composer` | 空串 | 全部探针 |

### 音符与量化

| 项 | 规则 | 证据 |
|---|---|---|
| 量化网格 | 1/4 拍（`MIDI_GRID = 0.25`） | 全部 |
| 取整方式 | **JS 式 `Math.round`**（逢五向上），不是 Python 的银行家舍入 | 输入 0.375 → 0.5 |
| 时值算法 | **原始时长（off−on）四舍五入到网格**，不是"量化终点 − 量化起点" | 0.40→0.50、0.65→0.75、0.90→1.00 |
| 最短发声 | **0.25 拍**（更短的一律按 0.25 算） | 0.10~0.35 全部→0.25 |
| 位置推进 | ★ **绝对对表**：pos = quant(原始起点)，cursor = max(cursor, pos+dur)；允许重叠与溢出 | 2026-10-12 用 25 首全量回归实锤（见第二节） |
| 音级/八度 | `degree` 取"不超过它的最大大调音级"，差值进 `acc`；八度以 C4(60)=0 | C#→[1,·,·,1]、C1(24)→八度 −3、C7(96)→八度 3 |
| 休止 | 音级 0、八度 0、升降 0；**空隙处显式补休止** | probe ② |
| 小节末尾 | **补休止把小节填满**（最后一小节也补） | probe ① |
| 跨小节 | 音符按小节线**切开** | probe ④：6 拍音 → 4.0 + 2.0 |
| 全曲无音 | 抛 `ValueError: 这个 MIDI 里没有音符` | probe F |

### 多音/重叠（单声化）

| 情形 | 原程序行为 | 证据 |
|---|---|---|
| 和弦（同一时刻多个音） | **只留音高最高的那个** | C-E-G → 只出 G |
| 高音在低音中间起 | 低音**被截断**到高音的起点 | A(0–2) + B(0.9–2) → A 1.0、B 1.0 |
| 低音在高音中间起 | 低音**整个被丢掉**，高音保持原长 | B(0–2) + A(0.5–1) → 只剩 B 2.0 |
| 同一音高重复按（已响时再按） | **忽略后一个 note on** | 0–2 与 1–3 重叠 → 只有一个 2.0 |
| 孤立的 note off | 忽略 | probe 2c |
| 相邻同音高的两个源音符 | **保留成两个音**，不合并 | 25 首回归里 3 首因此对齐 |

## 二、曾未定 / 已全部对齐（2026-10-12 实锤）

`verify/golden_regression.py` 当前 **25 / 25 首逐条一致**（解析层 + 动作层）。
原先 10 首的差异，根源是**一条规则**：小节划分不是"顺序装箱"，而是**绝对位置对表**：

> **每个音的位置 = 它自己原始起点的量化值**；游标 `cursor = max(cursor, pos + dur)`；
> gap = pos − cursor > 0 才补休止；小节按 `floor(pos / 拍数)` 归属，**允许溢出**
> （Σ4.25 > 4.0 是旧内核的真实行为，不裁）；结尾只补"最后一个音所落的小节"。

实锤过程（合成 MIDI 黑盒 + 真曲手算互相印证）：
* `刻我` bar9：两个极短音(0.09/0.052拍) 各显示 0.25 但位置对表 → 长音落在 35.25
  → 切小节得 0.75（顺序装箱模型只能得到 0.5）。
* `死别` bar1：绝对位置模型下自然多出 0.25 休止，Σ=4.25 与基准一致。
* `红尘客栈` bar42：两个 0.25 音**同占 167.25**（重叠显示）→ 后面 0.5 音不被挤掉。
* 旧探针 ⑤（3 个 32/64 分音符 → Σ4.25）也同时被该模型解释。

实现见 `hca/midi.py` 的 `_to_bars`（已重写为绝对位置版）。

## 三、顺带实锤的两条"文档与代码不符"

原程序自己的文档字符串里承诺过、但**代码里没有**的东西（对使用者有实际影响）：

1. **`[定位游戏窗口]` 按钮不存在** —— 没有任何窗口查找代码。程序是"事件发给系统，
   哪个窗口在前台就归谁收"。
2. **"会把鼠标停到不响应点击的位置"没实现** —— 没有 `SetCursorPos` 调用。
   所以鼠标当时若停在琴孔上，按移调键会**真的点下去**。
   → 新项目把这条**真做出来了**：`--park-cursor`（见 `hca/inputs.py` 的 `park/unpark`）。
