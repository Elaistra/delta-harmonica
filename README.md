# 三角洲口琴自动演奏

自动演奏程序：读 MIDI 曲库，编译成按键动作，再用 Windows 的 `SendInput` 发给屏幕上的口琴。  
纯 Python 标准库写成，零第三方依赖。

**许可：GPL-3.0**（见 `LICENSE`）。可以随便用、改、分发，但改过的版本必须同样以 GPL-3.0 开源。

它和原来的 `口琴自动演奏器.exe` 是完全分开的两个程序，各自独立运行、互不影响：

- 原程序是打包好的单个 exe，改不了；本程序是 Python 源码，可以随便改
- 两者共用同一个曲库目录，但**配置各管各的**（本程序用 `hca.json`，不碰原程序的配置）
- 内部代码包名叫 `hca`（harmonica autoplay 的缩写），只是技术细节

## 怎么拿到

**不想装 Python 的（推荐）**：到 Releases 页面下载 exe，双击就能用。

<https://github.com/xkrmand-web/delta-harmonica/releases>

下载下来的文件名是 `delta-harmonica-v1.0.0.exe` —— **GitHub 的 Release 附件不支持中文
文件名**（传上去会被强制改成 `default.exe`），所以附件名用了英文；程序本身、窗口标题

**想看源码或改代码的**：


也可以直接在 Releases 页面下载源码压缩包，或者在仓库页点 Code → Download ZIP。

## 运行

需要 Python 3.11 以上（实测 3.13 通过）。不需要安装任何第三方库。

```bash
python -m hca.ui              # 图形界面（也可以直接双击 run.bat）
python -m hca.ui --selftest   # 界面自检：不开窗口、不发按键
python -m hca.cli --list      # 命令行：列出曲库
python -m hca.cli --song 晴天 --dry-run      # 预演：只打印要按什么，不发键
python -m hca.cli --song 晴天 --countdown 3  # 真弹
python -m hca.cli --song 晴天 --rate 0.3     # 0.3 倍速慢练（支持 0.05 到 8 倍）
python -m hca.cli --info 晴天                # 只看解析结果
```

## 安全底线

这是本项目最重要的部分，写死在代码和自动化检查里：

**一、程序禁止修改任何内存** —— 游戏内存、别的进程内存、自己的进程内存都不改。  
**二、一切可能导致封号的操作都不许做。**  
只允许模拟键盘和鼠标，不允许任何带**修改性质**或**规避性质**的操作。

这不是口头承诺，而是能被自动拦住的：

```bash
python verify/redline_check.py             # 检查，违规则退出码 1
python verify/redline_check.py --selftest  # 先证明检查器真的抓得到（实测能抓出植入的 4 处违规）
```

检查器管四类：

- 改内存 / 碰进程（跨进程读写内存、远程线程、注入、钩子、调试、`PostMessage` 塞按键）
- 规避性质（输入伪装、内核驱动、进程伪装、反调试、清理痕迹、任何"伪装成人手"的手段）
- API 落点约束：只有 `hca/inputs.py` 和 `hca/hotkeys.py` 允许直接调 Windows API
- DLL 白名单：只允许 `user32`（SendInput / RegisterHotKey / 光标位置，都属于输入范畴）

当前状态是干净的。另外，**时间抖动（jitter）功能已主动删除** —— 它在游戏场景里唯一的  
实际用途是"让自动化显得不那么机械"，那就是规避性质，与第二条底线冲突。

### 必须直说的一个冲突

本程序发的是**合成输入**（`SendInput`）。Windows 会给合成输入打标记，低层钩子和 Raw Input  
能分辨出"这个键是不是程序合成的"。而游戏用户协议通常禁止自动化和宏 —— **这跟有没有改内存无关**。

所以在联网竞技游戏（如带 ACE 的《三角洲行动》本体）里自动演奏，**本身就落在底线二的范围内，  
封号风险无法降到零**。

| 环境                                | 封号风险     | 适用吗     |
| --------------------------------- | -------- | ------- |
| 自己写的网页版口琴 / 本机单机 / 模拟器 / 自己控制的客户端 | 没有       | 适用，随便用  |
| 联网竞技游戏本体                          | 有，且无法降到零 | 按底线二不该用 |

因此本项目默认按**通用工具**往下做，服务上表第一行：**不针对三角洲本体做键位适配，  
也不做任何"降低被发现概率"的事情**。

### 操作逻辑：与原程序逐项一致

| 项                  | 原程序                              | 本程序                      |
| ------------------ | -------------------------------- | ------------------------ |
| 对外手段               | 只有 `user32.SendInput`            | 同                        |
| 键盘                 | 发扫描码（游戏读 `e.code` 物理位置）          | 同                        |
| 鼠标                 | 按下/抬起三键当移调（左 −12 / 中 +1 / 右 +12） | 同                        |
| 读取游戏状态             | 完全没有                             | 没有                       |
| 改内存 / 注入 / 钩子 / 驱动 | 没有                               | 没有（且有 redline_check 自动拦） |
| 找窗口 / 锁定焦点         | 没有（谁在前台谁收）                       | 没有                       |
| 时间抖动 / 特征伪装        | 没有                               | 没有                       |

唯一的差异是一处改进：原程序文档承诺过但代码没实现的"发鼠标键前把光标挪开"，  
本程序**真做了**（`--park-cursor`），默认关闭。

### 管理员权限

原程序 exe 的 manifest 是 `requireAdministrator`；本程序通过 `run.bat` 自提权达到同一效果，  
每次启动会弹一次系统 UAC。

- 提权改变的是进程完整性级别：管理员发的合成输入可以作用于普通权限窗口
- 提权不改变事件性质：仍是 SendInput 合成输入，系统照样打标记
- 提权不是伪装也不是规避，风险与旧版持平、没有新增
- **仍未验证**：提权后按键在目标游戏里是否生效 —— 旧版也从未验证过这一点

## 功能

### 图形界面

双击 `run.bat` 打开（用 `pythonw` 启动，不弹黑框）。左侧是浮岛式侧边栏，  
页面包括演奏、收藏夹、热键、内置社区分享库、日志和设置。

- **演奏页**：曲库列表、当前曲目、当前音与要按的键、可拖动的位置条（拖到哪就从哪开始弹）、  
  播放控制、跳过前奏、循环、连奏防断音、速度滑条、倒计时、演奏预览
- **收藏夹页**（Soundpad 式两栏）：左栏收藏夹列表，右栏曲子。收藏夹只存在 `hca.json` 里，  
  **不挪动曲库文件**；一首曲子可以进多个收藏夹；双击曲目直接开始演奏
- **热键页**：任意条数的「组合键 ↔ 曲目」，现按现录，按下立即切换演奏
- **内置社区分享库页**：搜索 B 站三角洲口琴谱社区，列下载量/点赞，下载后转成 MIDI 存入曲库

### 曲库管理

命名、分类、批量删除、批量入夹。分类就是曲库下的子文件夹（旧版和游戏只读一层，  
看不到子文件夹里的曲子，正好当仓库用；本程序两层扫描，照常可选可弹）。  
**删除永远走系统回收站**（`hca/trash.py` 用 `SHFileOperationW` + `FOF_ALLOWUNDO`），可还原。

### 内置直连的 MIDI 下载站

程序里那个「内置社区分享库」页就是**内置直连的谱面下载站**，不经过我们自己的任何服务器，
也不要求你注册或配置：打开就能搜、能下载。

**这个方向是单向的：只下载，不上传。** 你本地曲库里的曲子不会被传上去 —— 整个项目里
只有 `hca/bili.py` 会联网，它只发五类请求：拿游客身份的两个 POST（请求体是空的），
以及搜索、统计、下载三个 GET。没有 PUT，没有multipart，没有任何文件上传。

- **网站**：B 站《三角洲行动》口琴谱社区（<https://www.bilibili.com/toy/deltaforce/index.html>）
- **程序直连的接口**：`https://111.229.198.119/v1`（这个地址是从社区页前端 JS 里取到的，
  证书是签给域名的，所以客户端要带 `Origin`/`Referer` 头，实现在 `hca/bili.py`）
- **怎么用**：关键词留空则按最新浏览，支持翻页；列表带下载量和点赞数。
  选一首或几首点下载，程序把它转成 MIDI 存进你的曲库，重名自动加 (2)(3)

下载到的是 raw deflate 压缩的 DFHS v1 二进制谱（格式已逆向，解码器也在 `hca/bili.py`），
转出来的 MIDI 是 format 0，和本地曲库里其他文件一样能直接弹。

需要说明的是：这个站是**玩家投稿的社区曲库**，不是严格意义上的开源乐谱站（比如 Mutopia、
MuseScore 那类）。它的价值是谱面本身就是为口琴改编的，拿来就能弹；代价是质量参差 ——
有些是音频自动扒的劣质谱（判断方法见「扒谱质量体检」一节）。

## 界面开发约定

改外观只需要动 `hca/ui.py` 顶部的几段常量：

- `SP` 间距，一律 4 的倍数
- `R` 圆角，**嵌套同心**：内层圆角 = 外层圆角 − 内边距
- `GLASS` 玻璃效果开关
- `Q` 阴影（颜色 / 扩散 / 下偏 / 层数）
- `THEME` 配色：暗调暖棕，底色 `#241F1B`、侧边栏 `#2B2520`、卡片 `#2E2822`、  
  字 `#F2EAE0` 奶油、强调色 `#C9703F` 陶土橙
- `PillSlider` 灵动岛滑块：激活时把手展开成黑岛，数值含在岛身里

字体用 **MiSans**（免费可商用，对标苹方）。苹方是 Apple 专有字体，不能合法分发。

几个实测踩过的坑，别改回去：

- `GLASS["extend_frame"]` 必须保持 `False`。开了会让整个客户区变玻璃，而 Tk 走 GDI 绘制、  
  像素 alpha 恒为 0，结果所有文字发白（实测最暗像素 143 vs 0）。
- 工作线程**绝不碰 Tk**（连 `var.get()` 都不行），否则报 `main thread is not in main loop`。  
  正确做法：主线程一次读好所有 Tk 变量传给 worker，worker 只往队列丢消息，主线程 `after()` 取。
- 画布上不要放盖住自绘内容的 frame，Tk 子窗口永远盖在画布直绘之上。
- 自绘控件必须绑 `<Map>` 事件强制重画，否则切页后可能永久空白。
- `st.map()` 的第二个位置参数是查询选项名，赋值必须用关键字参数形式。

## 怎么验证"发送侧"是对的

链路里最要紧又最没法求证的一环是「我们发的扫描码 → 对方读到的 `e.code`」。  
原程序整套设计押在这里，却从没端到端验证过，因为游戏那边看不见 —— 但浏览器看得见。

所以 `web/harmonica.html` 是自己搭的一台网页口琴：对着它弹一遍，录下它**实际收到**的事件，  
再和我们**该发**的逐条对。

```bash
python verify/web_conformance.py rec.json 动作表.json
```

- 能证明：扫描码到 `e.code` 的映射正确、孔位和移调算得对、事件顺序正确、时序偏差量级
- **不能证明**：《三角洲行动》本体的键位 —— 那只是我们自己的参照系
- 好处是本机网页，没有反作弊、没有封号风险

详见 `web/README.md`。

## 验收基准

用旧内核把 25 首曲子跑一遍，导出中间表示和全部动作（11,363 条）当基准，  
存在 `.workbuddy/analysis/golden_scores.json` 和 `golden_actions.json`。  
每完成一层就跑一次 `golden_regression.py`，**逐条比**而不是抽样。

这个基准让"像不像"从主观判断变成了数字。

注意：这些基准文件不在仓库里（`.workbuddy` 在上级目录），自己跑回归需要自备；  
曲库路径可以用环境变量 `HCA_LIB_DIR` 指定。

## 打包 / 发布

**零第三方依赖**，只用 Python 标准库，所以没有 requirements.txt。

```bash
pip install pyinstaller
pyinstaller harmonica.spec      # 产出 dist/三角洲口琴自动演奏.exe
```

两个容易踩的点，spec 里已经处理好了：

- **入口不能直接写 `hca/ui.py`**。它用包内相对导入（`from . import bili`），  
  当顶层脚本跑会报 `attempted relative import with no known parent package`。  
  所以需要 `main.py` 这个薄壳。
- **`mapping/` 必须作为资源带上**。运行时按「程序目录/mapping」找键位映射，丢了不会报错，  
  会**静默退回内置网页映射**，三角洲那份就没了。`web/` 也一并打包。

提交到 Git 之前：`.gitignore` 已经排掉了 `hca.json`（本机配置，含私人曲库路径、收藏夹、  
自定义热键）、`曲库/`、以及 `build/` `dist/`。别手动 `git add -f`。

代码里不写死任何一台机器的绝对路径：曲库默认是相对路径 `../曲库`，启动脚本用  
`%LOCALAPPDATA%` 找 Python，旧内核路径用环境变量 `HCA_LEGACY_PYC`。

## 发布前审查修掉的 bug（2026-10-12）

发布前做了一轮完整审查，下面每条都是**实测确认**过的，修复目标是不改变任何原有功能。

1. 空收藏夹时「加入收藏夹」给 Treeview 插入 `iid=""`（根节点） —— 会抛 TclError，  
   而 `grab_set()` 已经执行，模态框带着全局 grab 留在屏幕上，**整个界面锁死只能杀进程**
2. `start_hotkeys()` 不先 `stop()`，而 `Hotkeys.start()` 直接覆盖 `self._thread` ——  
   每改一次热键泄漏一条常驻线程，且旧组合键仍注册着，按下去会弹错曲
3. 下载的工作线程里调用了 `self.lib_path()`（内部读 `tk.StringVar`）—— 违反"工作线程不碰 Tk"
4. 旧播放线程迟到的 `done` 信号被照单全收 —— 新播放刚开始就被复位成"已停止"、进度条归零
5. `work()` 里直接 `self.player.play(...)` —— 切曲时旧线程会去驱动**新**的 player
6. `bind_all` 全局快捷键不判断焦点 —— 搜索框里打空格会开始演奏，列表按上下键会改速度
7. 重绘画布只删了 `"pill"`，漏掉卡片用的 `tag="shape"` —— 每张卡约 14 个 item 永不释放，  
   且旧尺寸的矩形会留成可见残影
8. `st.map()` 的第二个位置参数传了字符串（且不是 f-string） —— 复选框勾选色和 Spinbox  
   各态底色**从来没生效过**，是纯查询、静默失效
9. 删除曲目时 `e["song"] = new_base or e["song"]` 把 `None` 兜回原值 ——  
   下面的过滤永远删不掉，已删曲目的热键条目永久残留
10. `no_intro` / `loop` / `countdown` 只读不写回 —— 这三个设置关掉程序就丢
11. 倒计时期间被 stop 时漏了 `_quiet()`（另外两条分支都有） —— 移调键会卡住不放
12. `on_close()` 不 `join()` 播放线程 —— 可能把键卡在按下状态
13. 读不了的曲子不刷新预览区 —— 残留上一首的动作列表和总时长
14. 下载进度标签写死 `0/N` —— 下 20 首期间一直显示"下载 0/20…"

### 第二轮（2026-10-13，含 exe 实测报的那个）

15. **录制热键凭空多出 Alt**：Windows 下 Tk 的 `event.state` 位和 X11 不一样，  
    `0x0008` 是 **NumLock 指示灯位**、Alt 其实在 `0x20000`；老代码按 X11 的写法把  
    `0x0008` 当 Alt，于是 NumLock 开着时录 `Ctrl+1` 会得到 `Ctrl+Alt+1`。  
    顺带修了：按修饰键自己记账（Win 键的 state 位不可靠），主键改用 `event.keycode`  
    （虚拟键码）认 —— 之前 `Shift+1` 的 keysym 会变成 `exclam`，直接被判"注册不了"
16. **暂停会吃掉曲子**：`_wait_until` 拿墙钟减 `_t0` 算时刻，而 `pause()` 没重锚时间基准 ——  
    暂停多久就跳过多少音符（实测暂停 3 秒 = 吃掉 3 秒的曲子），暂停期间进度还在涨
17. **同一首已丢失的曲子在 2 个收藏夹里 → 启动崩溃**：丢文件那一栏按曲名当 `iid`，  
    第二遍插入撞重复 iid 抛 TclError，而这是在 `__init__` 里跑的，表现就是双击没反应
18. **热键"改绑"没生效**：弹窗写着"原条目会被替换"，实际只返回 bool 不删旧条目 ——  
    列表里留下两条同 key，按下去触发的是先注册的那条（旧曲子）
19. 删曲/改名后不重新注册全局热键 —— 删掉一条后下标整体前移，按旧组合键弹的是另一首
20. 畸形拍号的 MIDI 会**永久卡死**：分母是文件里一个字节，`2**255` 让小节长度趋近 0，  
    切小节的循环要跑天文数字次（不是异常，`try/except` 救不了）；分子为 0 则除零
21. 配置文件读不出来时直接返回默认值 —— 用户随手点一首曲子就 `save()` 覆盖原文件，  
    收藏夹和热键无声无息全丢。现在坏文件先另存一份 `.bad`，写盘改成"临时文件 + 整体替换"
22. 配置字段类型不校验：`"rate": "快"` / `"countdown": null` 会在 `__init__` 里炸（同样是"双击没反应"）
23. 关窗不保存设置页改动（键位映射 / 跳过前奏 / 循环 / 倒计时 / 曲库路径）
24. 每下载一首就全量重扫一次曲库（勾 20 首 = 解析全库 20 遍）；每按一次方向键变速就写一次整个配置
25. 重命名/删除当前曲目后 `self.current` 残留死路径 —— 右侧面板挂着旧曲名，重编译会去读不存在的文件
26. 社区库翻页带回重复 id 会让整批结果静默丢弃（`except` 把剩下的行一起吞了）

## 还没解决的问题

- **"按键在游戏里到底生不生效"从未在真实游戏里验证过**。重写内核解决不了这个问题 ——  
  原因在目标侧（反作弊 / 权限级别 / 焦点），本程序同样只是调 SendInput。
- **键位映射目前没有依据**。原程序那套键位是从网页复刻版逆出来的，三角洲本体是不是  
  同一套没有验证过。`mapping/delta_force.json` 是占位副本。
- **"逐条对齐旧版"和"加底层新玩法（和弦 / 多轨）"是互相冲突的两个目标**。  
  要跟旧版完全一样就别加新玩法；要新玩法就得接受和旧版有差异。
