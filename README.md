## 🚫 硬底线（用户定，不可协商）

> **① 程序禁止修改内存**（游戏内存、别的进程内存、自己的进程内存都不改）。>   
> **② 一切可能导致封号的操作都不许做。**>   
> **只允许模拟键盘和鼠标**，不允许任何带**修改性质**或**规避性质**的操作。

这条不是写在文档里给你看的 —— 它是**能被自动拦住**的：

```bash
python verify/redline_check.py             # 检查，违规则退出码 1
python verify/redline_check.py --selftest  # 先证明检查器真的抓得到
```

检查器管这些：

| 检查                   | 内容                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **禁止 A：改内存 / 碰进程**   | 跨进程读写内存（`WriteProcessMemory`/`ReadProcessMemory`/`Nt*VirtualMemory`）、远程线程与注入（`CreateRemoteThread`/`QueueUserAPC`）、钩子与调试（`SetWindowsHookEx`/`DebugActiveProcess`/`OpenProcess`）、内存扫描库（`pymem`/`frida`/`ptrace`）、绕过输入栈塞按键（`PostMessage WM_KEY*`） |
| **禁止 B：规避性质**（对应底线②） | 输入伪装（`interception`/`vmulti`/`ViGEm`/HID 伪造）、加载内核驱动（`NtLoadDriver`）、进程与窗口伪装、反调试探测、清理痕迹、任何形式的"绕过/规避/伪装成人手"                                                                                                                                      |
| **落点约束**             | 只有 `hca/inputs.py` 和 `hca/hotkeys.py` 允许直接调 Windows API                                                                                                                                                                                        |
| **DLL 白名单**          | 只允许 `user32`（SendInput / RegisterHotKey / 光标位置 —— 都是"输入"范畴）                                                                                                                                                                                    |

**当前状态：干净。** 全程只调了 user32 的输入相关 API；`--selftest` 实测能抓出植入的 4 处违规。

**顺带删掉的功能**：时间抖动（`jitter`）已移除。它在游戏场景里唯一的实际用途是  
"让自动化显得不那么机械"，那就是规避性质，与底线②冲突 —— 所以不留。

### 管理员权限（提权）：与原程序对齐（2026-10-12）

原程序 exe 的 manifest 是 `requireAdministrator`；新版通过 `run.bat` 自提权达到同一效果：  
未提权时用 `fltmc` 检测 → 弹系统 UAC 确认框 → 以管理员重启脚本。**每次启动都会弹一次 UAC**。

提权改变什么、不改变什么（机制层面）：

|         | 说明                                                          |
| ------- | ----------------------------------------------------------- |
| ✅ 改变    | 进程完整性级别：管理员发的合成输入可以作用于**中完整性**（普通权限）窗口——普通权限进程发的输入进不去高完整性目标 |
| ❌ 不改变   | 事件的**性质**：仍是 SendInput 合成输入，系统照样打标记；不读不改任何游戏内存              |
| ❌ 不改变   | 反作弊的识别面：该识别还是识别。提权不是伪装也不是规避，**风险与旧版持平、没有新增**                |
| ⚠️ 仍未验证 | "提权后按键在目标游戏里是否生效"——旧版也从未验证过这一点（只验证过声明生效）                    |

安全代价提醒：提权后整个 Python 解释器以管理员运行（旧版 exe 内嵌 Python 同样如此，  
**这一点与旧版等价**）。`redline_check` 照常拦截改内存/规避性 API。

## ⚠ 先看这三条（比代码重要）

### 1. 你选的目标是《三角洲行动》本体 —— 这件事会让"重写"白做

- **事实**：原程序靠 `SendInput` 发扫描码模拟真键鼠。
- **预测（未验证）**：三角洲用 ACE 反作弊。反作弊**可能拦截或标记**合成输入。    
  如果是这样，**新写一个 Python 程序还是调 SendInput，结果和旧程序一样**——    
  因为它解决的是"程序写得对不对"，而你遇到的问题在"目标收不收"。
- **结论**：**重写内核不能解决"按键不生效"。** 要先验证"发送这一侧到底通不通"：    
  在三角洲里用旧程序跑一遍，看有没有反应。没反应的话，先别投入重写。

### 2. 键位映射目前**没有依据** —— 这是最硬的一个缺口

原程序那套键位（`Z X C V B N M ,` + 鼠标三键移调）是从**网页复刻版**（app.js）逆出来的。  
**三角洲本体是不是同一套，没有验证过。**（这台机器上也没找到那个网页版的文件。）

所以映射被抽成了**可插拔 JSON**（`mapping/`）：  
换游戏只改配置、不改代码。`mapping/delta_force.json` 现在是**占位副本**，  
`source` 标着 `TODO` —— 程序会在启动时警告，别拿它演奏。

**怎么补**（约 10 分钟，需要你在游戏里做）：见本文件末尾的「键位采集表」。

### 3. 封号风险

在正式游戏里用自动化工具演奏，通常违反游戏用户协议，可能被判定为宏/机器人。  
**这个风险由你承担。** 我不做任何针对反作弊的规避手段 —— 那条线不碰。

### ★ `extend_frame` 必须保持 False —— 否则全部文字发白（实测）

"边框延伸"（`DwmExtendFrameIntoClientArea`）会把**整个客户区**变成玻璃，DWM 于是按  
alpha 通道合成。但 **Tk 走 GDI 绘制，GDI 写出来的像素 alpha 恒为 0** —— 结果整块内容  
（含所有文字）都被 DWM 当成半透明去和背景混合，**字全部发白、发虚**。

这不是猜的，是量出来的（同一台机器，同一段文字区域 620..1080 × 120..340）：

| 设置                   | 最暗像素          | 标准差  |
| -------------------- | ------------- | ---- |
| `extend_frame=True`  | **143 / 255** | 10.0 |
| `extend_frame=False` | **0 / 255**   | 30.8 |

用 `PrintWindow` 和屏幕 DC 两种抓法各测一遍，结论一致 —— 不是截图假象。  
所以现在的分工是：**窗口边框**用系统亚克力（真玻璃），**客户区**用实色（字清晰），  
**卡片**的玻璃感靠高光 / 描边 / 阴影画出来。  
想要全窗真玻璃就把 `GLASS["extend_frame"]` 改回 True —— 代价是字发白。

### 关于"液态玻璃"—— 能做到什么程度（实测）

**Tk 本身没有背景模糊能力**（模糊是系统合成器的活）。所以玻璃感分三层实现，我**实测过**：

| 层             | 手段                                                                           | 本机实测结果                               |
| ------------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| **窗口级（真模糊）**  | `DwmSetWindowAttribute` 亚克力背景 + `DwmExtendFrameIntoClientArea` 让客户区"透明"处露出模糊 | **HRESULT = 0 ✔ 生效**（但会让字发白，故默认关掉延伸） |
| **窗口级（原生圆角）** | `DWMWA_WINDOW_CORNER_PREFERENCE`                                             | **HRESULT = 0 ✔ 生效**                 |
| **卡片级**       | 近白填充 + 1px 顶边高光 + 1px 冷灰描边 + 多层渐淡阴影                                          | 画布绘制                                 |

机检环境：Windows 11 24H2（build 26100）。**不支持的系统会自动退化成纯色底**，  
侧边栏底部会显示"玻璃：不可用（纯色底）"。  
看着不对就改 `GLASS["backdrop"] = "none"` —— 一行回到纯色。

### 灵动岛滑块（不用 ttk.Scale）

`ttk.Scale` 的滑道和把手都是方的，观感上还是"老式音量条"。所以两个滑块  
（演奏位置 / 速度）都换成了自己画的 `PillSlider`：

| 状态                        | 长相                                                           |
| ------------------------- | ------------------------------------------------------------ |
| **静止**                    | 细胶囊轨道（已走过的部分填强调色）+ 白色小胶囊把手，带下投影和细描边                          |
| **激活**（按下/拖动/←→/Home/End） | **把手展开成黑色"灵动岛"，把当前数值含进岛身里** —— 就是 iPhone 灵动岛的行为：小药丸变大、内容长在岛里 |

点轨道任意位置直接跳过去，不用精准命中把手；键盘也能操作。  
数值格式可自定义（位置显示 `1:08`，速度显示 `1.00×`）。

### 三级明度（底色必须比卡片深）

白卡片要"浮"得起来，底色就得比卡片深一档，而且是**一级一级递进**：

| 层     | 颜色        | 亮度  |
| ----- | --------- | --- |
| 画布底色  | `#E6E8EE` | 233 |
| 浮岛侧边栏 | `#EFF1F6` | 242 |
| 内容卡片  | `#FFFFFF` | 255 |

之前底色 `#F2F2F7` 和卡片只差 13 阶，整片发平 → 视觉疲劳。  
这个层次关系有自检断言守着（`底色 < 侧边栏 < 卡片`）。

### 解析层补齐 25/25 —— 旧版正式无可替代（2026-10-12 第八轮追加）

按文档"别猜、先打原始事件"的方法，用真曲原始 note on/off + 基准结果手算，发现  
10 首差异根源是**一条规则**：小节划分不是"顺序装箱"（先来的音把位置往前推），  
而是**绝对位置对表**——每个音落在 `quant(自己的原始起点)`，游标取  
`max(cursor, pos+dur)`，允许音重叠、小节溢出（Σ4.25>4.0 是旧内核真实行为）。  
重写 `hca/midi.py` `_to_bars` 后：

- **解析层 25/25 逐条一致**（原 15/25），**动作层 25/25 完全一致**    
  （11,363 条动作逐条相同，原 15 首可比）。
- 旧版从此没有新版做不到的功能；`exe_extracted` 仍不删（回归基准的生成源）。
- 规则已固化进 `docs/解析规则-实测.md` 第二节（含死别/刻我/红尘客栈三个实锤样例）。

## 怎么用

**双击 `run.bat`** → 打开界面。想用命令行（在本仓库目录下）：

```bash
python -m hca.cli --list                          # 列曲库
python -m hca.cli --song 晴天 --dry-run            # 预演：只打印要按什么，不发键
python -m hca.cli --song 晴天 --countdown 3        # 真弹（默认就是自己的内核）
python -m hca.cli --song 晴天 --rate 0.3           # 0.3× 慢速跟练（原程序界面做不到）
python -m hca.cli --info 晴天                      # 只看解析结果

python -m hca.ui --selftest                       # 界面自检（不显示窗口、不发按键）
python -m hca.cli --song 晴天 --dry-run --engine reference   # 借旧内核对同一首，用于对照

python verify/golden_regression.py --actions      # ★ 验收：解析层 + 动作层逐条比
python verify/redline_check.py                    # ★ 底线：不改内存、不碰规避性质的 API
```

> **自己的内核只依赖标准库**，Python 3.11+ 就能跑（实测用系统 3.13 通过）。>   
> `--engine reference` 是把原 exe 里的字节码当库加载，**只用于对照**，需要 Python 3.14。
>
> **一条开发纪律**：`Player` 的回调是在**工作线程**里触发的。>   
> 所以界面里**工作线程绝不碰 Tk** —— 只往 `_ui_events` 队列丢消息，主线程用 `after` 取。>   
> 违反这条会报 `main thread is not in main loop`（我踩过一次，界面自检抓出来了）。

`run.bat` 是等价的双击入口。

## 验收基准（`verify/` 怎么来的）

## 打包 / 发布

**依赖：零第三方库。** 只用到 Python 标准库（tkinter / ctypes / urllib 等），  
Python 3.11+ 即可（实测 3.13 通过）。所以 `pip install -r requirements.txt` 这步是**没有的**。

### 源码运行

```bash
python -m hca.ui            # 图形界面
python -m hca.ui --selftest # 界面自检（不开窗口、不发按键）
python -m hca.cli --list    # 命令行
```

### 封成 exe

```bash
pip install pyinstaller
pyinstaller harmonica.spec      # 产出 dist/口琴演奏器-新版.exe
```

两个易踩的点，spec 里已经处理好了：

| 坑                       | 说明                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **入口不能直接写 `hca/ui.py`** | 它用包内相对导入（`from . import bili`），当顶层脚本跑会报<br />`attempted relative import with no known parent package`。所以有 `main.py` 这个薄壳 |
| **`mapping/` 必须作为资源带上** | 运行时按「程序目录/mapping」找键位映射。丢了不会报错，会**静默退回内置网页映射**，三角洲那份就没了                                                                  |

`web/`（自建网页口琴）也一并打包，`run.bat` 菜单第 8 项会打开它。

### 提交到 Git 之前

`.gitignore` 已经排掉了这些，**别手动 `git add -f`**：

## 发布前审查修掉的 bug（2026-10-12）

发布前做了一轮完整审查，下面每条都是**实测确认**过的（不是看代码猜的），  
修复目标是不改变任何原有功能。

| #  | 问题                                                                    | 后果                                                 |
| -- | --------------------------------------------------------------------- | -------------------------------------------------- |
| 1  | 空收藏夹时「加入收藏夹」给 Treeview 插入 `iid=""`（根节点）                               | **抛 TclError，而 `grab_set()` 已执行 → 界面被模态框锁死，只能杀进程** |
| 2  | `start_hotkeys()` 不先 `stop()`，而 `Hotkeys.start()` 直接覆盖 `self._thread` | 每改一次热键泄漏一条常驻线程；旧组合键仍注册着，按下去弹错曲                     |
| 3  | 下载工作线程里调用了 `self.lib_path()`（内部读 `tk.StringVar`）                      | 违反"工作线程不碰 Tk"，会抛 `main thread is not in main loop` |
| 4  | 旧播放线程迟到的 `done` 信号被照单全收                                               | 新播放刚开始就被复位成"已停止"、按钮被启用、进度条归零                       |
| 5  | `work()` 里直接 `self.player.play(...)`                                  | 切曲时旧线程会去驱动**新**的 player（两条线程共弹一个）                  |
| 6  | `bind_all` 全局快捷键不判断焦点                                                 | 搜索框里打空格 → 开始演奏；列表按 ↑↓ 选曲 → 顺手把速度改了                 |
| 7  | 重绘画布只 `delete("pill")`，漏了卡片用的 `tag="shape"`                           | 每张卡约 14 个 item 永不释放，且旧尺寸矩形留成可见残影                   |
| 8  | `st.map()` 第二个位置参数传了字符串（且非 f-string）                                  | 复选框勾选色、Spinbox 各态底色**从来没生效过**（纯查询，静默失效）            |
| 9  | 删除曲目时 `e["song"] = new_base or e["song"]` 把 `None` 兜回原值               | 下面的过滤永远删不掉 → 已删曲目的热键条目永久残留                         |
| 10 | `no_intro` / `loop` / `countdown` 只读不写回                               | 这三个设置关掉程序就丢                                        |
| 11 | 倒计时期间被 stop 时漏了 `_quiet()`（另两条分支都有）                                   | 移调键卡住不放                                            |
| 12 | `on_close()` 不 `join()` 播放线程                                          | 可能把键卡在按下状态                                         |
| 13 | 读不了的曲子不刷新预览区                                                          | 残留上一首的动作列表和总时长                                     |
| 14 | 下载进度标签写死 `0/N`                                                        | 下 20 首期间一直显示"下载 0/20…"                             |

顺带清理：`config.py` 默认的 `lib_dir` 和 `run.bat` 里的 Python 路径**原本写死了本机绝对路径**  
（会带出去私人目录结构），已分别改成相对路径 `../曲库` 和 `%LOCALAPPDATA%\...`。

想验证**发送侧真的通**（扫描码 → `e.code`），再加一条人工流程：  
打开 `web/harmonica.html` 并聚焦 → 录制 → 跑演奏 → `verify/web_conformance.py` 对账。
